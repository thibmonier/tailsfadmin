# ADR-005 : Internationalisation & support RTL

## Statut

**Accepté** (2026-09-07)

## Contexte

La version Laravel de TailAdmin gère **4 langues** (`en`, `ar`, `es`, `de`) avec un middleware `SetLocale`, un `LocaleController` (route `/locale/{locale}`, persistance session + cookie, gestion de la **direction `dir` LTR/RTL** pour l'arabe). **Aucun catalogue de traduction n'est fourni** dans les sources — ils sont à recréer. Le layout doit anticiper le **RTL** (arabe) dès sa conception (US-006, US-024).

## Décision

- **Traductions** : utiliser le composant **Translation** de Symfony (catalogues dans `translations/`). Créer `en` et `fr` **complets** (langues de référence du projet) ; fournir la **structure** (clés) prête pour `ar`, `es`, `de`. `fallback_locale: en`.
- **Sélection de locale** : un **`EventSubscriber`** (kernel.request, priorité élevée) résout la locale dans l'ordre **session → cookie → `default_locale`**, valide contre une **liste blanche** de locales supportées (rejet → fallback), puis positionne `Request::setLocale()`. (Équivalent Symfony du middleware `SetLocale` Laravel.)
- **Changement de locale** : une route `GET /locale/{locale}` (contrôleur du **bundle**, avec garde whitelist) stocke la locale **et la direction `dir`** (ltr/rtl) en session + cookie (1 an), puis redirige vers la page précédente.
- **RTL** : exploiter les variantes Tailwind **`ltr:` / `rtl:`** sur marges/positions/flottants dès le layout et la sidebar ; l'attribut `dir` est posé sur `<html>` selon la locale. Le dark mode et le RTL sont **orthogonaux** (combinables).
- **Sélecteur de langue** : composant Twig (dropdown) affichant nom natif + drapeau + direction, alimenté par la configuration des locales supportées (métadonnées inspirées de `LocaleController::SUPPORTED_LOCALES`).

## Alternatives considérées

| Option | ✅ | ❌ |
|--------|----|----|
| **Composant Translation + EventSubscriber (choisi)** | Idiomatique Symfony, testable, RTL géré proprement | Catalogues à recréer (absents des sources) |
| Locale uniquement via `_locale` dans l'URL | Standard Symfony, cache-friendly | Moins proche du comportement TailAdmin (session/cookie) ; combinable plus tard |
| Ignorer le RTL au départ | Moins de travail initial | ❌ Refactor coûteux du layout ensuite ; l'arabe est une langue cible |

## Conséquences

### Positives
- i18n complète et extensible ; **RTL de première classe** anticipé dès le layout.
- Le bundle fournit le mécanisme (subscriber, route, sélecteur) ; l'app hôte fournit/complète ses catalogues.

### Négatives / vigilance
- **Recréer les catalogues** `en`/`fr` (US-024) ; `ar`/`es`/`de` en structure.
- Tester la combinatoire **dark × RTL** sur les composants clés (sidebar, dropdowns, modals).
- Décider si la route de locale et le subscriber sont **activables/désactivables** via la config du bundle (défaut : activés dans la démo, optionnels pour un consommateur qui a déjà sa stratégie i18n).
