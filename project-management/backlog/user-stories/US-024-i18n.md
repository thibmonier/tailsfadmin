# US-024 — Internationalisation (i18n) et sélecteur de langue

**EPIC :** EPIC-006-pages-i18n · **Statut :** 🔴 To Do · **Points :** 8 · **Priorité :** Should · **Sprint :** backlog

## Carte (Card)
> En tant que **P-003 — Mainteneur du bundle**, je veux **intégrer un système d'internationalisation complet (catalogues de traduction `en`/`fr` minimum, structure prête pour `ar`/`es`/`de`, sélecteur de langue persistant, gestion LTR/RTL)**, afin de **permettre à tout intégrateur d'adapter l'interface d'administration à sa langue cible sans modifier le bundle**.

## Conversation
La référence Laravel du projet (`Tools/sources/tailadmin-laravel-main/`) implémente l'i18n via un middleware `SetLocale` (`app/Http/Middleware/SetLocale.php`) qui lit la locale depuis la session, un `LocaleController` (`app/Http/Controllers/LocaleController.php`) exposant la route `GET /locale/{locale}` et stockant la locale en session, et un composant dropdown `resources/views/components/common/dropdown-menu.blade.php` servant de sélecteur de langue dans le header. Les 4 langues supportées sont `en`, `ar` (RTL), `es`, `de`. Aucun catalogue de traduction n'est fourni dans les sources : ils doivent être recréés côté Symfony dans `bundle/translations/` (format XLIFF 2.0 ou YAML, domaine `tailsfadmin`). Les clés de traduction couvrent a minima les libellés du layout (navigation, header, footer du bundle). L'intégration Symfony utilise : `Symfony\Component\HttpKernel\Event\RequestEvent` ou un `EventSubscriber` pour lire la locale depuis la session (équivalent du middleware Laravel), une route `GET /locale/{locale}` dans le bundle (`LocaleController.php`), et le composant `LanguageSwitcher` (Live Component ou Twig Component + lien) dans le header (US-007). La gestion RTL pour l'arabe impose `<html dir="rtl" lang="ar">` et un fichier CSS additionnel `bundle/assets/styles/rtl.css` appliquant les overrides Tailwind nécessaires (`flex-row-reverse`, marges inversées, etc.). Les catalogues `fr` et `en` doivent être complets ; `ar`, `es`, `de` peuvent être partiels (structure en place, traductions à compléter par la communauté). La locale est persistée en session (cookie de session Symfony). L'intégrateur peut étendre le bundle avec ses propres catalogues via le mécanisme de fallback Symfony Translator.

## Confirmation — Critères d'acceptation (Gherkin)
### Scénario nominal
```gherkin
Feature: Sélecteur de langue et changement de locale
  Scenario: Changement de langue vers le français depuis le header
    Given l'application de démo est en locale "en" (défaut)
    And le sélecteur de langue est visible dans le header
    When l'utilisateur clique sur le sélecteur et choisit "Français"
    Then une requête GET est envoyée vers "/locale/fr"
    And la session stocke la locale "fr"
    And la page est rechargée avec tous les libellés du bundle traduits en français
    And l'attribut "lang" de la balise <html> passe à "fr"
```
### Scénarios alternatifs
```gherkin
  Scenario: Persistance de la locale entre les pages
    Given l'utilisateur a sélectionné la locale "fr" et est sur la page dashboard
    When il navigue vers la page "/profile"
    Then la page profil s'affiche avec les libellés en français sans aucune action supplémentaire

  Scenario: Activation du mode RTL pour l'arabe
    Given l'utilisateur sélectionne la locale "ar"
    When la page se recharge
    Then l'attribut "dir" de la balise <html> est "rtl"
    And la sidebar s'affiche à droite de l'écran
    And les textes et icônes sont miroirs conformément au design RTL de TailAdmin

  Scenario: Locale inconnue transmise en URL
    Given un utilisateur appelle manuellement "/locale/zh"
    When le LocaleController traite la requête
    Then la locale "zh" est ignorée et la locale par défaut "en" est conservée
    And l'utilisateur est redirigé vers la page précédente sans message d'erreur

  Scenario: Fallback vers l'anglais pour une clé manquante
    Given le catalogue "fr" ne contient pas encore la clé "tailsfadmin.chart.no_data"
    When Symfony tente de traduire cette clé en locale "fr"
    Then le Translator retourne la traduction anglaise "No data available" (fallback)
    And aucune exception n'est levée
```
### Scénarios d'erreur
```gherkin
  Scenario: Fichier de catalogue XLIFF malformé
    Given le fichier "translations/tailsfadmin.fr.xlf" contient un XML invalide
    When Symfony charge le cache de traduction ("cache:warmup")
    Then la commande échoue avec une exception "InvalidResourceException" indiquant le fichier concerné
    And le message d'erreur précise la ligne XML incorrecte

  Scenario: Session détruite entre deux requêtes (locale perdue)
    Given l'utilisateur avait sélectionné la locale "es"
    When sa session expire ou est invalidée côté serveur
    Then la locale retombe sur la valeur par défaut "en" définie dans "config/packages/translation.yaml"
    And aucune erreur 500 n'est générée
```

## INVEST
- **Independent :** L'i18n est un système transversal mais techniquement isolable ; n'impose pas de modification des composants UI existants (uniquement l'ajout de clés de traduction).
- **Negotiable :** Le nombre de langues complètes au sprint de livraison est négociable ; `en`+`fr` complets est le minimum accepté, les autres en structure.
- **Valuable :** Critère différenciateur du bundle par rapport aux thèmes Laravel-only ; ouvre le bundle à un public international.
- **Estimable :** Middleware/EventSubscriber Symfony, catalogues, contrôleur de locale, composant sélecteur, CSS RTL ; 8 points reflètent la complexité transversale.
- **Small :** Périmètre clairement borné : traductions du bundle uniquement (pas des pages applicatives de l'intégrateur).
- **Testable :** Changement de locale, persistance session, `dir=rtl`, fallback traducteur — tous testables par tests fonctionnels et unitaires.

- **Bloque :** US-025 (a11y — les attributs `lang` et `dir` sont requis)
